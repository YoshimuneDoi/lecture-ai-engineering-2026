# 提出用の実行記録（v2）

受講者提供の端末ログ2本と、後から添付された追記出力ファイル1本を照合して整理・復元した記録です。整理のためにモデルを再実行してはいません。

## 読み方

- `a_run01.txt`〜`a_run03.txt`：モデルAの先頭3回答。主要比較。
- `a_run04.txt`：モデルAの追加回答。
- `initial_38_run01.txt`：当初の比較先で返った503の記録。
- `initial_38_run02.txt`：当初の比較先を手動中断した際のトレースバック。
- `b_run01.txt`：モデルBの1回目。503により回答なし。
- `b_run02.txt`〜`b_run04.txt`：モデルBの取得回答3件。すべて主要比較。
- `source_logs/`：提供された原ログ・追記ファイルをバイト単位でそのまま保存。
- `manifest.json`：各試行の対応、コマンドと根拠、原ログの行位置、SHA-256（Secure Hash Algorithm 256-bit：内容照合用のハッシュ値）、未計測項目。

## 追記ファイルの重複を除く方法

`source_logs/model_b_alt_3_appended.txt` の1〜32行は既存B3と完全一致するため、別試行として数えません。33〜71行の別回答だけをB4として追加しました。B3を保存している原ログが2本あることと、試行が2回あったことを混同しないようにしています。

A2・A3は同じ元ファイル名を使用していたため、現在の既存resultsファイル名だけでは実行順が分かりません。本フォルダでは実行順に統一しました。接続確認の「日本の首都」やセットアップ操作は、宿題10試行に含めません。

抽出ファイルはUTF-8・LF改行にそろえ、先頭末尾の空行を整理しました。回答の文章は修正していません。元の改行を含む原本はsource_logsに保存しています。

`.gitattributes` は証拠のテキストにGitの自動改行変換を適用しない設定です。原ログについては元からある行末空白を修正対象にしません。各内容はmanifest.jsonのSHA-256で照合できます。

## 集計と未計測項目

宿題10実行、7回答取得、503が2回、手動中断が1回。主要比較はA3回答・B3回答、Aの追加回答1件も保存しています。timeout作動は記録上確認されません。

B4の出力ファイルには実行コマンド・日時がありません。コマンドと90秒／追加5秒の設定は、受講者提示の実行画面image(7).pngを根拠としてmanifestに記載しました。画像はこの公開用パックに含めていません。実際の応答時間、日時・間隔、トークン数、SDK内部の通信回数は未取得・不明です。
